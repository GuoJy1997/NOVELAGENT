# 笔心：作者自编工作流节点系统设计规格

日期：2026-08-24
状态：已评审（对话中逐节确认）

本文细化《2026-08-15-hermes-shell-kernel-design.md》第 6 节「工作流通道」：定义节点类型、节点配置、附件类型、图格式与执行语义。不推翻内核规格的任何红线；冲突时以内核规格为准，除非本文第 10 节明确点名。

相关文档：

- 视觉：`2026-08-14-bixin-desktop-home-visual-design-system.md`（画布 UI 属笔心框内，另开计划）
- 远期：编号规格 10（Agent 编排）、14（技能系统）仅作方向参考，不按其全量实现

## 1. 精髓

一张图 = 作者精打细算排好的一条生产线。节点是工位，skill 是刀头，模型是马力，线只传附件。Hermes 每次只跑一个节点、一轮，不许改路线、不许加节点、没有对话入口。

节点的能力不写死在笔心前端：节点存的是 **skill 引用 + 专家引用 + 模型名 + 目标文本 + 输入槽**，skill 正文住在 Hermes 的技能目录里，画布通过现有 `/hermes/v1/skills` 清单选用。换刀头不用改画布。

## 2. 节点类型

十类。每类声明：吃什么（输入槽）、吐什么（附件还是候选）。**附件**不改真文件，落盘可缓存；**候选**进 `drafts/`，作者接受后才覆盖真文件。

### 2.1 探索节点（读状态）

- 目标示例：「盘点全书写到哪了：已完成章、未回收伏笔、人物当前状态」
- 输入：无（直接读书目录真文件）
- 输出：附件（`事实` 或 `报告` 类型），落盘缓存，下游引用文件而不是每轮重读全书
- 参考实现思路：voocel/ainovel-cli 按伏笔、角色出场、状态变化、关系四维反查相关历史章节，不做全文通读

### 2.2 基因提取节点（拆书）

- 目标示例：「从《某书》提取骨架、文笔、悬念构造、恐怖点营造」
- 输入：一本外部小说文本（上传路径或书目录内文件）
- 输出：附件（`基因` 类型），存入本书 `genes/<来源名>.md`，是**可复用资产**：提一次，之后任何写作节点都能挂
- 硬边界（版权）：产物只含抽象后的叙事模型、语言指纹、技法规则与风格边界，**不含原句、原段、可替代原文阅读的情节复述**。规则入选须满足复现性（同书出现不止一次）、生成力（能指导新场景）、排他性（不是所有小说通用的废话）
- 参考：XTmingyue/wenfeng-skill（六层规则）、CloudLiu1008/distill-novels（多书、按维度、防串书）、sevenwoood/quill-skill（多风格配比融合）

### 2.3 大纲节点（规划）

- 目标示例：「按总纲拆第二卷卷纲与章纲」
- 输入：探索附件、基因附件（可选）
- 输出：候选，指向 `outline.md`
- 与写作节点分列的理由：产物指向不同真文件、上游约束不同、适配模型不同

### 2.4 写作节点（正文）

- 目标示例：「写第 15 章」「写某个子故事」，粒度写在目标里
- 输入：探索附件、大纲附件或候选引用、基因附件（可选）、审查报告附件（重跑时）
- 输出：候选，指向 `chapters/ch_NN.md`
- 「开篇」不是独立节点：开篇钩子、章末钩子、打脸爽点等是写作节点上**可选的 skill**（参考 hackiey/ai_creator 391+ 方法论 skill 的组织方式）
- 去 AI 味规则可作为第二个 skill 挂在本节点上**边写边防**（见 2.5）

### 2.5 去 AI 味节点（洗稿）

- 目标示例：「消除本章 AI 痕迹，保留事实与风格承载细节」
- 输入：正文候选引用；**作者文字样本**（可选独有输入槽，voice calibration 用）
- 输出：候选，指向同一真文件路径（覆盖上游候选为新版本）
- 双模式：独立节点事后洗一遍；或将同一 skill 挂到写作节点边写边防。两者不互斥
- 参考：blader/humanizer（维基 35 模式）、taxue2025/say-it-human（中文 12 维 + 浓度分级）、Shirhussain/humanize（voice calibration + 确定性 linter）、ruijayfeng/zh-writing-humanizer（中文语境感知）

### 2.6 审查节点（出报告，不动文件）

- 目标示例：「审第 15 章：OOC、设定一致性、逻辑、文笔、重复、爽点、追读力」，维度可勾选
- 输入：正文候选引用 + 设定附件（世界观、关系）
- 输出：附件（`报告` 类型）。**审查意见永远是附件，不是候选**（内核规格已定）
- 报告须定位到具体句段并给出改法，不许「整体感觉不错」式空评（wgwtest/novel-writing 的立场）
- 参考维度库：PhosAQy/novel-skills 五维（OOC / Lore / Logic / Style / Repetition）、lingfengQAQ/webnovel-writer 追读力系统（Hook / 爽点 / 微兑现 / 债务追踪）

### 2.7 记忆沉淀节点（写状态）

- 目标示例：「第 15 章已接受：提取新事实、更新伏笔台账、刷新人物状态快照」
- 输入：已接受的真文件（章节）
- 输出：候选，指向状态类真文件（事实账、伏笔台账、时间线；具体文件布局在实现计划定）
- 探索节点的镜像：探索读状态，沉淀写状态。没有它写到几十章必吃书——所有能撑到百万字的仓库（webnovel-writer、ai_creator、ainovel-cli）都以此为命根
- 典型挂法：接在人工节点（作者接受章节）之后

### 2.8 门禁节点（条件分支，不跑模型）

- 目标示例：「审查报告综合分 < 80 → 打回写作节点，最多重试 2 次；否则放行」
- 输入：报告附件
- 输出：路由决策（不产附件、不产候选）
- **红线**：循环边、阈值、最大重试次数全部由作者摆图时画死。模型不能改路线；门禁只是按作者预设的条件走预设的边。重试耗尽仍不过 → 节点标受阻，等作者
- 判分来源：报告附件中结构化分数字段（实现计划定格式）；无分数字段则门禁只支持人工放行

### 2.9 人工节点（作者检查点）

- 目标示例：「停在这里，作者选一个方向再继续」「作者审基因资产」
- 输入：任意附件
- 输出：作者的决定（放行 / 选项 / 一句话补充，作为附件传下游）
- 图跑到人工节点即暂停，笔心亮出待办；作者不点，下游永远不跑。长图没有人工检查点，跑完 20 个节点才发现第 2 步歪了

### 2.10 研究节点（可选，MVP 不做）

- 目标示例：「查民国邮政系统资料，整理进世界观参考」
- 输入：无
- 输出：附件（`事实` 类型）
- 依赖 Hermes 侧的联网搜索能力；等对应 skill 就绪再接（参考 chianglianglin/novel-writer 的 `/novel-research`）

## 3. 节点配置（每个节点一样的槽位）

| 槽位 | 说明 |
|---|---|
| 目标 | 作者写的一段话，含粒度（第几章、哪个子故事） |
| skill | 从 `/hermes/v1/skills` 清单选，可多选（如 写作 + 去 AI 味）。**不存 prompt 正文，只存引用** |
| 专家 | 从 Hermes 专家清单选，可空 |
| 模型 | 默认继承图的全局模型；单节点可覆盖。审查用快而便宜的，正文用最强的——模型只在需要判断的位置被精确使用 |
| 输入槽 | 声明本节点吃哪些类型的附件 / 候选引用；缺了标受阻 |
| 独有槽 | 个别节点专属：去 AI 味的作者文字样本、基因提取的外部书路径、门禁的阈值与重试上限 |

模型槽走笔心已接好的 Hermes 模型路由（请求体 `model` 字段），不直连任何模型商。

## 4. 附件类型系统

线是有类型的。摆图时就校验「审查节点要求上游有正文候选引用」，不合法的连线画不上去，而不是跑到一半才受阻。

| 类型 | 产自 | 例 |
|---|---|---|
| `事实` | 探索、研究 | 进度盘点、人物状态快照 |
| `报告` | 审查 | 定位到句段的审查意见 + 结构化分数 |
| `基因` | 基因提取 | `genes/<来源名>.md` 的引用 |
| `候选引用` | 大纲、写作、去 AI 味、记忆沉淀 | 指向 `drafts/<run-id>/` 里某条候选 |
| `作者决定` | 人工 | 放行 / 选项 / 补充说明 |

线只传附件与候选引用，不传聊天记录（内核规格原话）。附件一律落盘在本书目录 `workflow/attachments/`，节点间传文件引用。

## 5. 图格式与存储

- 图存本书目录（如 `workflow/graphs/<图名>.json`），可版本化、可复制给别的书当模板
- 内容：节点数组（类型 + 配置槽）+ 有向边数组（源、目标、附件类型、是否循环边 + 重试上限）
- 运行实例另存（`workflow/runs/<run-id>/`）：每节点状态（待跑 / 跑完 / 受阻 / 失败 / 等作者）、产物引用、耗时与 token
- 具体 JSON schema 在实现计划里定，本文只锁上述信息集合

## 6. 执行语义

- 文件核（`services/api`）按拓扑序调度；Hermes 只跑单节点单轮
- 一个节点一轮：目标 + skill 提示词 + 专家提示词 + 上游附件 → 打包成一次 Hermes 请求（复用对话通道同一条 `/hermes/v1/chat/completions` 链路与候选核）
- 缺上游附件：节点不跑，标受阻，不让 Hermes 编造上下文
- 节点失败：停在失败处，已落候选不删，真文件不动
- 门禁循环：只走作者预画的循环边，次数耗尽标受阻
- 人工节点：暂停整条下游，等作者
- Hermes 不在：整图离线，已有候选与附件保留
- 探索 / 基因附件带缓存：输入未变（源文件指纹一致）时可直接复用上次产物，作者可强制重跑

## 7. skill 来源与装配

skill 全部住在 Hermes 侧技能目录，笔心只读清单。把 GitHub 上的成熟 skill 装进 Hermes（多为标准 `SKILL.md` 格式，基本免改造），画布即刻可选：

| 分类 | 推荐装配 |
|---|---|
| 写作 / 开篇 | hackiey/ai_creator 方法论集、wgwtest/novel-writing、chianglianglin/novel-writer（15 作家人格竞写思路） |
| 审查 | PhosAQy/novel-skills 五维、lingfengQAQ/webnovel-writer 追读力维度 |
| 去 AI 味 | blader/humanizer、taxue2025/say-it-human、ruijayfeng/zh-writing-humanizer、Shirhussain/humanize |
| 基因提取 | XTmingyue/wenfeng-skill、CloudLiu1008/distill-novels、sevenwoood/quill-skill |
| 记忆 / 状态 | lingfengQAQ/webnovel-writer 记忆闭环、wgwtest/novel-project-strategy 章节状态纪律 |

装配注意：逐个过一遍再装，删平台绑定内容（Claude Code 专属命令等）；中文写作优先中文原生 skill；许可证以 MIT 为主，随附来源与许可声明。

## 8. 基因资产库

- 位置：本书目录 `genes/`；一个来源一个 markdown
- 生命周期：基因提取节点产出 → 人工节点作者过目 → 入库；写作 / 大纲节点通过输入槽挂用
- 跨书复用：允许作者手动把 `genes/` 文件拷到另一本书；MVP 不做全局基因库
- 版权红线同 2.2：抽象规则可存，原文不可存

## 9. MVP 边界（这一版不做）

- 研究节点（2.10）
- 全局基因库、基因资产分享
- 图模板市场
- 并行分支的并发执行（MVP 串行拓扑即可）
- 把对话框的 todo 转成图（内核规格明令禁止）
- 画布 UI 本身按内核规格第 9 节仍是最后一步，另开计划；本文的图格式与执行器可先用 JSON 文件 + 测试夹具落地

## 10. 与既有规格的关系

- 细化而非推翻：内核规格「探索节点 / 动手节点」二分展开为十类，附件 / 候选二分保持不变
- 「单章 / 一幕 / 一卷」固定配方继续当过渡替身；本文执行器落地后，用三张预置图复刻三个配方，然后下线 `recipeRunner.ts` 写死的五步（时机在实现计划定）
- 仍有效：笔心唯一直播 UI、候选经作者接受才落盘、`relations.md` 投影、api `8787`、hermes `8642`、不引入 Tailwind

## 11. 验收

- 作者能用 JSON（无画布）定义一张「探索 → 写作（挂开篇 skill + 基因附件）→ 去 AI 味 → 审查 → 门禁（<80 打回，最多 2 次）→ 人工」的图并跑通
- 每个动手节点的产物只出现在候选区；接受后才进真文件
- 拔掉一条上游线，下游节点标受阻且不跑
- 审查报告能定位到句段；门禁按分数走预画的边；重试耗尽标受阻
- 基因文件里搜不到源书任何连续原句
- Hermes 关掉，整图报离线，已有候选完好
