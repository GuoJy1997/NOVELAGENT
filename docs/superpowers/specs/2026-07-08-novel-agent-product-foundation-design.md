# Novel-Native Agent Product Foundation Design

日期：2026-07-08

状态：Review Candidate

## 1. 文档目的

这份文档是“小说原生 Agent 软件”在进入单模块 spec 之前的产品底座。它解决三个问题：

1. 明确 MVP 第一版边界，防止每个模块无限膨胀。
2. 把需求从功能清单拆到可写 spec 的层级。
3. 统一后续所有模块 spec 的数据对象、入口、工作流、Agent 边界、模型路由和长期记忆规则。

这份文档不是单个功能的详细 spec，也不是前端 UI 实现计划。后续每个模块会基于这份底座分别写独立 spec。

## 2. 产品定位

小说原生 Agent 软件不是普通写作编辑器，也不是单纯的聊天式写作助手。它的核心定位是：

> 一个面向长篇小说创作的 Agent Cockpit，能够围绕一本小说维护灵感、大纲、人物、世界观、线索、章节、审查、记忆和模型调度，并把复杂创作目标拆成可执行任务。

产品的第一性价值是：

- 帮作者从灵感进入结构化创作。
- 让复杂长篇小说的线索、伏笔、人物、设定不会散。
- 让 Agent 不只是生成文本，而是能拆任务、调模型、调 Skill、维护记忆、产出可审查结果。
- 让作者通过可视化地图、泳道图、关系图看清故事结构。

## 3. 推荐拆解方案

产品拆解采用“工作流优先，模块承载，Agent 驱动”的方式。

### 3.1 不采用纯模块拆解作为主线

纯模块拆解会得到灵感库、人物、世界观、章节写作、审查、模型切换等独立模块。这个方式方便管理，但容易把产品做成一组孤岛功能。

### 3.2 不采用纯 Agent 能力拆解作为主线

纯 Agent 能力拆解会先做 Agent 编排、Skill、模型路由、长期记忆，再往上挂功能。这个方式技术架构漂亮，但早期用户不容易感受到“我真的能用它写小说”。

### 3.3 采用工作流优先拆解

MVP 主线按作者真实创作路径组织：

```text
灵感进入
  ↓
灵感结构化
  ↓
进入大纲 / 篇章泳道图 / 人物 / 世界观 / 线索
  ↓
章节写作
  ↓
章节审查
  ↓
修改任务
  ↓
发布前审核
```

模块 spec 按系统模块落地，底层由 Agent 编排、Skill、模型路由和长期记忆支撑。

## 4. MVP 边界

MVP 第一版要证明一件事：这个软件能围绕一本小说建立结构、管理线索、辅助写作、审查章节，并通过 Agent 编排完成复杂创作任务。

### 4.1 MVP 必须包含

| 模块 | MVP 范围 |
|---|---|
| 小说项目系统 | 创建、进入、管理一本小说；每本小说独立存储数据 |
| Novel Cockpit | 作为小说入口层，展示结构地图、当前任务、Agent 状态和关键模块入口 |
| 灵感库系统 | 按小说存储灵感；灵感可分类、关联、转成任务或结构节点 |
| 大纲 / 篇章系统 | 管理全书结构、篇章结构、章节结构 |
| 篇章泳道图系统 | 一个重要篇章对应一个泳道图，展示剧情推进与伏笔推进 |
| 人物系统 | 人物卡、基础人物关系、人物与章节 / 线索 / 世界观关联 |
| 世界观系统 | 设定条目、设定分类、设定关联、基础冲突提示 |
| 线索 / 伏笔系统 | 线索卡、伏笔卡、线索链、线索归因、回收状态 |
| 章节写作系统 | 基于大纲、人物、设定、线索和记忆生成章节草稿 |
| 审查 / 修改系统 | 章节逻辑、人物、节奏、伏笔、AI 感审查，并生成修改任务 |
| Agent 编排系统 | 拆分任务、派发 Subagent、调用 Skill、汇总结果 |
| Skill 系统 | 提供写作、审查、修改、线索、人物、世界观等单项能力 |
| 模型切换 / 模型路由系统 | 按任务选择模型，展示模型特点，支持手动覆盖 |
| 长期记忆系统 | 按小说隔离记忆，维护核心设定、人物、世界观、线索、文风 |
| 可视化系统 | 全书结构地图、篇章泳道图、人物关系图、线索关系图的 MVP 版本 |
| 发布审核系统 | 发布前格式、敏感风险、重复表达、章节钩子和基础质量检查 |

### 4.2 MVP 不包含

| 能力 | 第一版不做的原因 |
|---|---|
| 多人协作 | 会引入权限、冲突合并和团队流程，分散 MVP 主线 |
| 真实平台一键发布 | 需要平台接口、账号授权和合规处理，可放到 V2 |
| 收益分析 | 与“小说创作 Agent”核心闭环距离较远 |
| 评论反馈自动分析 | 依赖发布和读者数据，适合发布系统成熟后加入 |
| 完整移动端 | MVP 以桌面 Cockpit 为主，移动端只考虑基础响应式 |
| 本地模型部署管理 | 与模型路由不同，属于高阶技术配置 |
| 图片生成工作流 | 可支持图片灵感入库，但不把生图作为 MVP 主功能 |
| 复杂权限系统 | MVP 单用户项目优先 |

### 5.1 L0：产品层

```text
小说原生 Agent 软件
```

### 5.2 L1：系统层

```text
13. 模型切换 / 模型路由系统

```

| 灵感库系统 | 灵感创建、灵感分类、灵感状态、灵感关联、灵感转任务 / 转节点 |
| 大纲 / 篇章系统 | 故事核心、卷纲、篇章、章节、场景、节奏模板 |

| 线索 / 伏笔系统 | 线索卡、伏笔卡、线索链、暗线链、误导线索、回收检查 |
| 章节写作系统 | 章节草稿、场景写作、续写、扩写、改写、润色、降 AI 感 |
| 审查 / 修改系统 | 逻辑审查、节奏审查、人物审查、伏笔审查、发布审查、修改任务 |
| Agent 编排系统 | 任务拆分、任务依赖、任务派发、任务重启、结果合并、人类确认 |
| Skill 系统 | 写作 Skill、审查 Skill、修改 Skill、线索 Skill、人物 Skill、世界观 Skill |
| 模型路由系统 | 模型注册表、模型档案、任务推荐模型、手动切换、成本提示、失败降级 |
| 长期记忆系统 | 项目记忆、核心设定记忆、人物记忆、世界观记忆、线索记忆、文风记忆 |
| 可视化系统 | 结构地图、泳道图、人物关系图、世界观图、线索图、任务图、记忆图 |
| 发布审核系统 | 平台格式、敏感风险、标题简介、章节钩子、重复表达、质量清单 |

### 5.4 L3：用户任务层

L3 是后续写具体 spec 的最小用户目标层。每个 L3 任务应能被写成一个清晰的 spec 或一个 spec 内的独立用例。

| L1 系统 | 优先 L3 用户任务 |
|---|---|
| 小说项目系统 | 创建一本小说；进入一本小说；配置目标平台；归档小说 |
| Novel Cockpit | 查看全书结构；聚焦某个篇章；查看当前 Agent 任务；跳转到灵感库 |
| 灵感库系统 | 快速存入灵感；把灵感转成人物；把灵感转成线索；把灵感转成泳道节点 |
| 大纲 / 篇章系统 | 创建篇章；创建章节大纲；把章节挂到篇章；调整章节顺序 |
| 篇章泳道图系统 | 创建事件节点；创建伏笔节点；连接节点；填写线索提供者 / 触发者 / 接收者 |
| 人物系统 | 创建人物；编辑人物目标；建立人物关系；把人物关联到线索 |
| 世界观系统 | 创建设定条目；建立设定关联；标记设定揭露章节；检查设定冲突 |
| 线索 / 伏笔系统 | 创建线索链；种下伏笔；记录误导线索；检查未回收伏笔 |
| 章节写作系统 | 基于章节卡生成草稿；续写章节；按文风润色；生成下章钩子 |
| 审查 / 修改系统 | 审查单章；生成修改任务；应用修改建议；复审章节 |
| Agent 编排系统 | 输入目标并拆任务；派发 Subagent；重启失败任务；汇总结果 |
| Skill 系统 | 选择 Skill；查看 Skill 说明；执行 Skill；保存 Skill 输出 |
| 模型路由系统 | 查看模型特点；切换任务模型；接受推荐模型；查看成本提醒 |
| 长期记忆系统 | 写入核心设定；引用人物记忆；发现记忆冲突；回滚记忆版本 |
| 发布审核系统 | 发布前检查章节；优化标题简介；生成发布清单 |

### 5.5 L4：Spec 层

L4 是正式 spec 文档层。每个 spec 必须回答：

- 用户从哪里进入？
- 用户输入什么？
- 系统输出什么？
- 数据对象如何变化？
- Agent 做什么？
- Skill 做什么？
- 模型如何选择？
- 长期记忆读写什么？
- 可视化如何呈现？
- 异常情况如何处理？
- 怎么验收？

## 6. 核心数据模型

所有创作数据必须归属于某一本小说。灵感库、记忆、人物、世界观、线索不能做成全局混用。

### 6.1 核心对象

| 对象 | 含义 |
|---|---|
| Novel | 一本小说项目 |
| NovelSettings | 小说配置，包括类型、目标平台、默认模型、默认风格 |
| Volume | 分卷，可选 |
| Arc | 篇章 / 重要故事单元；一个 Arc 对应一个或多个泳道图 |
| Chapter | 章节 |
| Scene | 场景 |
| SwimlaneDiagram | 某个 Arc 的泳道图 |
| Swimlane | 泳道，如剧情推进、线索伏笔、人物弧光 |
| EventNode | 泳道图里的事件节点 |
| Character | 人物 |
| CharacterRelation | 人物关系 |
| WorldItem | 世界观设定条目 |
| Clue | 线索 |
| Foreshadowing | 伏笔 |
| ClueChain | 线索链 / 伏笔链 |
| Inspiration | 灵感 |
| AgentTask | Agent 任务 |
| SubagentProfile | 子代理角色 |
| SkillDefinition | Skill 定义 |
| ModelProfile | 模型档案 |
| MemoryItem | 长期记忆条目 |
| ReviewReport | 审查报告 |
| RevisionTask | 修改任务 |
| PublishChecklist | 发布审核清单 |

### 6.2 对象关系

```text
Novel
  ├─ NovelSettings
  ├─ Inspirations
  ├─ Characters
  │   └─ CharacterRelations
  ├─ WorldItems
  ├─ Volumes
  │   └─ Arcs
  │       ├─ SwimlaneDiagrams
  │       │   ├─ Swimlanes
  │       │   └─ EventNodes
  │       └─ Chapters
  │           └─ Scenes
  ├─ ClueChains
  │   ├─ Clues
  │   └─ Foreshadowing
  ├─ AgentTasks
  ├─ MemoryItems
  ├─ ReviewReports
  └─ RevisionTasks
```

### 6.3 关键建模原则

1. `Novel` 是数据隔离边界。
2. `Arc` 是篇章泳道图的主要归属对象。
3. `EventNode` 是剧情、线索、人物弧光、世界观揭露的交叉点。
4. `ClueChain` 必须能追踪提供者、触发者、接收者、误导者、隐藏者、回收点。
5. `MemoryItem` 必须记录来源，不能只存结论。
6. `ModelProfile` 不绑定供应商实现，系统通过模型注册表扩展模型。

## 7. 信息架构与入口层

### 7.1 主入口结构

```text
项目列表
  ↓
小说 Cockpit
  ↓
全书结构地图
  ↓
篇章泳道图
  ↓
章节 / 人物 / 世界观 / 线索 / 灵感 / 审查
```

### 7.2 Novel Cockpit 是核心入口层

用户进入一本小说后，首先进入 Novel Cockpit。它不是普通首页，而是小说项目的驾驶舱。

Cockpit 必须展示：

- 当前小说卡片。
- 全书结构地图。
- 篇章泳道图入口。
- 灵感库入口。
- 人物关系图入口。
- 世界观入口。
- 线索关系图入口。
- 当前章节写作入口。
- Agent 任务队列。
- 模型路由状态。
- 长期记忆同步状态。
- 发布审核状态。

### 7.3 右侧 Agent Orchestration 面板

右侧面板应常驻在桌面 Cockpit 中，作为“指挥台”。

它展示：

- 当前任务。
- 排队任务。
- 运行中的 Subagent。
- 可用 Skill。
- 当前任务使用模型。
- 推荐模型。
- 记忆调用状态。
- 审查清单。

## 8. 核心工作流

### 8.1 创建小说

```text
用户输入书名、类型、简介、目标平台
  ↓
系统创建 Novel 和 NovelSettings
  ↓
Agent 生成初始项目结构建议
  ↓
系统创建默认模块：灵感库、人物库、世界观、线索库、大纲、记忆空间
  ↓
进入 Novel Cockpit
```

关键规则：

- 新小说创建后必须拥有独立灵感库和记忆空间。
- 初始结构建议必须由用户确认后才写入核心大纲。

### 8.2 存入灵感

```text
用户随手输入灵感
  ↓
系统自动归属到当前 Novel
  ↓
Agent 判断灵感类型
  ↓
存入 Inspiration
  ↓
用户选择是否转成人物、线索、世界观、章节节点或 AgentTask
```

关键规则：

- 灵感默认不直接改写核心设定。
- 灵感转结构对象时必须保留来源引用。

### 8.3 创建篇章泳道图

```text
用户选择一个 Arc
  ↓
系统创建 SwimlaneDiagram
  ↓
默认创建剧情推进、线索 / 伏笔、人物弧光、世界观揭露泳道
  ↓
用户添加 EventNode
  ↓
用户连接因果箭头
  ↓
线索类节点填写提供者、触发者、接收者、回收点
```

关键规则：

- 一个重要篇章至少对应一个泳道图。
- 泳道图是该篇章内事件推进、线索推进、人物变化和设定揭露的统一视图。

### 8.4 写章节

```text
用户选择 Chapter
  ↓
系统加载章节大纲、相关人物、世界观、线索、记忆和文风
  ↓
模型路由推荐写作模型
  ↓
章节写作 Skill 生成草稿
  ↓
草稿进入章节审查
```

关键规则：

- 章节生成不能只依赖用户临时 prompt。
- 必须加载与章节相关的结构化上下文。

### 8.5 审章节

```text
系统读取章节文本
  ↓
审查 Agent 调用审查 Skill
  ↓
检查逻辑、人物、节奏、伏笔、设定、AI 感
  ↓
生成 ReviewReport
  ↓
拆成 RevisionTask
  ↓
用户确认修改
```

关键规则：

- 审查报告必须能定位到章节段落或相关结构对象。
- 自动修改必须经过用户确认，除非用户开启低风险自动修订。

### 8.6 Agent 自动拆任务

```text
用户输入目标，例如“帮我完善第二篇章”
  ↓
Agent Orchestrator 拆分任务
  ↓
系统生成任务依赖图
  ↓
分配 Subagent
  ↓
模型路由选择模型
  ↓
Subagent 调用 Skill
  ↓
系统汇总结果
  ↓
关键改动等待用户确认
```

关键规则：

- Agent 可以建议结构改动，但不能静默覆盖核心设定。
- 失败任务必须可重启。
- 每个任务必须保留输入、调用模型、调用 Skill、输出和状态。

## 9. 篇章泳道图设计基线

### 9.1 一个泳道图代表什么

一个泳道图代表一个重要篇章或完整故事单元。一本小说由多个篇章泳道图组成，用户先在全书结构地图中看到所有篇章，再拖拽、缩放、聚焦到具体泳道图。

### 9.2 默认纵向泳道

MVP 默认泳道：

1. 剧情推进。
2. 线索 / 伏笔。
3. 人物弧光。
4. 世界观 / 设定揭露。

V2 可扩展泳道：

- 情绪张力。
- 阵营 / 权力冲突。
- 主题表达。
- 时间 / 空间变化。

### 9.3 事件节点字段

每个 EventNode 至少包含：

- 节点名称。
- 节点类型：剧情、线索、伏笔、人物、世界观、反转、高潮、回收。
- 所属 Novel。
- 所属 Arc。
- 所属 Chapter / Scene。
- 所属 Swimlane。
- 故事内时间。
- 地点。
- 参与人物。
- 触发者。
- 线索提供者。
- 线索接收者。
- 观察者。
- 隐藏者。
- 误导者。
- 回收者。
- 事件结果。
- 对主线的作用。
- 对伏笔的作用。
- 后续回收点。
- 关联 Clue / Foreshadowing / Character / WorldItem。

### 9.4 线索节点强约束

如果节点类型是线索或伏笔，必须至少填写：

- 谁提供了线索。
- 谁触发了线索。
- 谁接收或观察到线索。
- 线索可信度。
- 预期回收位置。
- 当前状态：已种下、推进中、已误导、已回收、废弃。

## 10. Agent、Subagent、Skill 边界

### 10.1 Agent Orchestrator

Agent Orchestrator 是总调度层，负责：

- 理解用户目标。
- 拆分任务。
- 判断依赖关系。
- 分配 Subagent。
- 选择模型。
- 调用 Skill。
- 合并结果。
- 请求用户确认高风险改动。

### 10.2 Subagent

Subagent 是持续职责角色，适合承担跨步骤任务。

MVP 默认 Subagent：

| Subagent | 职责 |
|---|---|
| Story Architect | 大纲、篇章结构、节奏与故事骨架 |
| Clue Weaver | 线索、伏笔、暗线、误导和回收 |
| Lore Keeper | 世界观、设定、规则一致性 |
| Character Editor | 人物卡、人物弧光、人物关系与动机 |
| Chapter Writer | 章节草稿、续写、改写、润色 |
| Critic Sage | 审查、质量评估、修改建议 |
| Publish Auditor | 发布前格式、风险和清单检查 |

### 10.3 Skill

Skill 是单项能力，适合短任务或可复用动作。

MVP 默认 Skill：

- 结构分析。
- 大纲生成。
- 章节写作。
- 对话打磨。
- 降 AI 感。
- 节奏调优。
- 人物一致性检查。
- 线索种植。
- 伏笔回收检查。
- 世界观冲突检查。
- 发布审核。
- 标题 / 简介优化。

### 10.4 判断规则

| 问题 | 做成什么 |
|---|---|
| 是单次可复用能力吗？ | Skill |
| 是一个持续职责角色吗？ | Subagent |
| 需要拆任务、排依赖、汇总结果吗？ | Agent Orchestrator |
| 只是页面上的普通编辑行为吗？ | 普通功能 |
| 会影响核心设定、人物死亡、结局、重大反转吗？ | 必须人类确认 |

## 11. 模型切换 / 模型路由系统

模型切换不是简单下拉框，而是模型调度中心。每个模型必须有档案，每类任务必须有推荐模型规则。

### 11.1 模型档案字段

`ModelProfile` 至少包含：

- id。
- name。
- provider。
- strengths。
- weaknesses。
- bestFor。
- avoidFor。
- speedLevel。
- costLevel。
- contextLength。
- creativityLevel。
- reasoningLevel。
- writingLevel。
- reviewLevel。
- supportsTools。
- supportsVision。
- supportsLongContext。
- recommendedTaskTypes。

### 11.2 模型类型与特点

| 模型类型 | 特点 | 适合任务 | 不适合任务 |
|---|---|---|---|
| 创意发散模型 | 想象力强、点子多、表达活 | 灵感、桥段、人物关系、设定脑暴 | 严格逻辑审查 |
| 深度推理模型 | 逻辑强、结构分析好、能处理复杂关系 | 大纲、暗线、伏笔、世界观规则、任务拆分 | 快速批量润色 |
| 长文本写作模型 | 上下文容量大、适合连续写作 | 长章节、多章续写、文风保持 | 超低成本任务 |
| 高速轻量模型 | 快、便宜、响应及时 | 摘要、标签、简单改写、格式整理 | 复杂剧情推理 |
| 审校模型 | 稳定、保守、擅长发现问题 | 逻辑审查、人物一致性、设定冲突、发布审核 | 高创意生成 |
| 风格模仿模型 | 文风贴合度高、语气保持强 | 润色、续写、降 AI 感、作者风格保持 | 多线复杂规划 |
| 多模态模型 | 能理解图片、图谱、视觉资料 | UI 草图、人物图、世界观图、视觉灵感解析 | 纯文本高性价比任务 |
| 工具调用模型 | 擅长调用数据库、文件、检索和工作流工具 | Agent 编排、记忆检索、自动审查、任务执行 | 单纯文学表达 |

### 11.3 默认模型路由规则

| 任务类型 | 推荐模型 |
|---|---|
| 灵感发散 | 创意发散模型 |
| 大纲制作 | 深度推理模型 |
| 篇章泳道图规划 | 深度推理模型 |
| 线索 / 伏笔设计 | 深度推理模型 |
| 世界观规则检查 | 深度推理模型或审校模型 |
| 章节草稿 | 长文本写作模型 |
| 文风润色 | 风格模仿模型 |
| 单章审查 | 审校模型 |
| 发布审核 | 审校模型或高速轻量模型 |
| 任务编排 | 工具调用模型 |
| 记忆检索与合并 | 工具调用模型或深度推理模型 |

### 11.4 用户可见能力

用户必须能看到：

- 当前默认模型。
- 当前任务模型。
- 系统推荐模型。
- 推荐理由。
- 成本等级。
- 速度等级。
- 上下文能力。
- 手动切换入口。
- 高成本提醒。

## 12. 长期记忆系统

长期记忆必须按小说隔离。系统可以有用户偏好记忆，但小说创作记忆不能跨小说污染。

### 12.1 记忆类型

| 记忆类型 | 内容 |
|---|---|
| Project Memory | 小说目标、题材、平台、整体风格 |
| Core Canon Memory | 已确认不可随意改动的核心设定 |
| Character Memory | 人物身份、目标、秘密、关系、弧光 |
| World Memory | 世界观规则、历史、阵营、地理、文化 |
| Clue Memory | 线索、伏笔、暗线、误导、回收状态 |
| Style Memory | 作者文风、句式偏好、禁用表达 |
| Workflow Memory | 用户常用流程、常用模型、常用 Skill |

### 12.2 记忆写入规则

- 灵感默认不进入核心记忆。
- 用户确认后的设定可进入核心记忆。
- 章节写作产生的新事实必须经过审查或用户确认后写入记忆。
- 审查发现的冲突不直接改记忆，而是生成冲突报告。
- 每条记忆必须记录来源对象和创建时间。

### 12.3 记忆冲突处理

当新内容与旧记忆冲突时，系统必须提供：

- 冲突双方。
- 冲突原因。
- 涉及章节 / 人物 / 设定。
- 建议处理方式。
- 用户选择：保留旧记忆、采用新记忆、合并、标记为平行版本。

## 13. 用户角色

### 13.1 新手作者

目标：从零搭故事。

核心需求：

- 引导式大纲。
- 人物与世界观模板。
- 自动拆任务。
- 章节草稿生成。

### 13.2 连载网文作者

目标：稳定更新，不忘伏笔，不崩设定。

核心需求：

- 章节状态卡。
- 存稿管理。
- 伏笔追踪。
- 节奏审查。
- 发布审核。

### 13.3 强设定作者

目标：维护复杂世界观。

核心需求：

- 世界观图谱。
- 设定规则检查。
- 历史、阵营、地理、文化管理。
- 长期记忆。

### 13.4 悬疑 / 推理作者

目标：管理线索、误导、反转和回收。

核心需求：

- 线索链。
- 暗线链。
- 线索归因。
- 可信度标记。
- 泳道图。

### 13.5 编辑 / 审稿人

目标：快速发现问题并转成修改任务。

核心需求：

- 单章审查。
- 跨章一致性检查。
- 修改任务拆分。
- 发布审核清单。

## 15. 统一 spec 模板

每个功能 spec 使用同一结构：

```text
# 功能名称

## 1. 功能定位
这个功能解决什么问题。

## 2. 用户角色
谁会用它。

## 3. 入口位置
从哪里进入。

## 4. 核心用户目标
用户想完成什么。

## 5. MVP 范围
第一版做什么。

## 6. 非 MVP 范围
第一版不做什么。

## 7. 核心流程
按步骤描述用户如何完成任务。

## 8. 数据对象
涉及哪些数据模型。

## 9. 字段定义
每个对象有哪些字段。

## 10. 状态机
有哪些状态，如何流转。

## 11. Agent 行为
Agent 在这里做什么。

## 12. Skill 调用
会调用哪些 Skill。

## 13. 模型选择规则
默认用什么模型，何时切换。

## 14. 长期记忆读写
读取什么记忆，写入什么记忆。

## 15. 可视化要求
是否需要图、卡片、泳道、关系线。

## 16. 异常情况
失败、冲突、缺字段时怎么办。

## 17. 验收标准
怎么判断做完了。

## 18. 后续版本
V2 / V3 可以扩展什么。
```

## 16. 单模块 spec 的验收标准

每份后续 spec 必须满足：

1. 有明确入口。
2. 有明确用户目标。
3. 有 MVP 与非 MVP 边界。
4. 有结构化数据对象。
5. 有状态流转。
6. 有 Agent 行为边界。
7. 有 Skill 调用说明。
8. 有模型路由规则。
9. 有长期记忆读写规则。
10. 有异常情况处理。
11. 有可测试的验收标准。
