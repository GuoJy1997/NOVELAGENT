# 笔心本地 MVP 工作台设计规格

日期：2026-08-15
状态：已评审

参考：镜界写作 Mirroric（https://www.mirroric.cn/）的信息架构与功能划分；Agent 内核沿用本机 hermes-agent。本规格覆盖「自己能天天写」的最小闭环，不实现 15 篇产品规格的全量系统。

## 1. 目标

本地跑通一本小说：作者改设定、改关系、改大纲，Agent 按范围产出候选正文，作者接受后写入章节文件。

证明三件事：

1. Agent 能按 GUI 工作流编排产出：单章、一卷（副本）、一幕（多章）。
2. 人物关系图谱给人看；交给模型的是投影后的可读文件。
3. 世界观是编辑功能，Agent 只读、不擅自改。

## 2. 从 Mirroric 取什么、不取什么

镜界写作是「长篇 AI 写作台」：设定、人物、大纲一处管理，边写边对照；作品保存在本机。应用层分成作品库与书内工作台。书内模块包括概览、创作（章节树 + 编辑器 + 助手）、大纲、人物、关系图谱、世界观/设定、伏笔，以及智能体、技能、工作流、任务看板。主笔之外有子智能体（情节顾问、人物声音、世界观考据）。工作流是可安装到「本小说」的图编排，并宣传五步人机协作。

### 2.1 采用

| Mirroric | 笔心 MVP |
|---|---|
| 侧栏按创作对象划分，写作台是主战场 | 侧栏：首页、写作、大纲、人物、关系、世界观、任务 |
| 章节树 + 正文 + 助手三栏 | 写作页沿用该骨架，右侧 Echo 为助手 |
| 关系图谱一等公民 | 独立「关系」页，不是人物页里的装饰图 |
| 世界观/设定是资料编辑 | 世界观页只编辑 `world.md` |
| 主笔 + 子智能体 | Echo 主笔；`@` 唤起专家（情节顾问、人物声音、世界观考据、结构） |
| 本小说工作流、任务看板、逐步执行 | 三种配方安装到当前书；任务卡逐步打勾 |
| 五步人机协作 | 读上下文 → 起草 → 自检 → 落候选 → 作者接受 |
| 技能挂在写作动作上 | `/` 唤起 Skill：扩写、润色、续写、单章/一幕/一卷 |
| 作品只在本机 | `.novelora-data/`，无云同步 |

### 2.2 明确不做（对照 Mirroric 全量）

- 通用节点画布（拖节点、连线、循环、定时运行）
- 拆书工作流、圆桌会议、独白模式
- 地图 / 势力 / 生物 / 物品 作为独立模块（需要时写进 `world.md`）
- 伏笔台账（下一轮）
- 创作资产库、十套主题、快捷方式编辑器
- 向量 RAG、云账号

工作流 GUI 在 MVP 里是**任务卡 + 步骤列表**，视觉参考 Mirroric 任务看板（条目、状态、时间线连接），不是流程图编辑器。三种配方够你自己写；节点画布等配方稳定后再做。

## 3. 信息架构

侧栏与笔心首页现有「首页 / 项目 / 大纲 / 人物 / 统计 / 世界观」对齐，按 Mirroric 书内模块改一版：

| 导航 | 页面 | 作者在此做什么 | Agent 看到什么 |
|---|---|---|---|
| 首页 | 现有仪表盘 | 继续写作、进度、入口 | 无 |
| 写作 | 章节树 + 编辑器 + Echo | 写正文、跑配方、对话 | 当前章 + 配方上下文 |
| 大纲 | Markdown 编辑 | 改全书/卷/幕/章纲 | `outline.md` |
| 人物 | 人物卡列表与详情 | 改身份、目标、知情 | `characters.json` 投影进 `relations.md` 的人物段 |
| 关系 | 图谱 | 拉节点、改边 | 仅 `relations.md` |
| 世界观 | Markdown 编辑 | 改规则、地理、势力 | `world.md` |
| 任务 | 任务看板 | 选配方、看步骤、接受/丢弃候选 | `tasks/*.json` |

统计仍可留在首页卡片，不单独占 MVP 导航。设置放侧栏底，本轮只做模型默认值。

进入规则：首页「继续写作」进写作页并选中当前章。侧栏「写作」同样进入写作页。

## 4. 项目文件（唯一事实源）

```text
.novelora-data/<book-id>/
  project.json
  outline.md
  world.md
  characters.json
  relations.md
  canon.md
  chapters/ch_01.md
  drafts/<task-id>/ch_01.md
  tasks/<task-id>.json
```

约定：

- `project.json`：书名、卷/幕/章树、当前章、已安装配方、默认模型。
- `outline.md`：人编大纲，Agent 只读，除非作者在聊天里接受「写入大纲」。
- `world.md`：人编世界观。Agent 禁止直接覆盖。
- `characters.json`：图谱与人物卡的结构化源（id、姓名、角色、坐标可选）。
- `relations.md`：由 `characters.json` 投影生成的纯文本，**Agent 读关系只读这一份**。不含像素坐标、颜色、UI 状态。
- `canon.md`：已锁定短事实。宁可空，不要臆造。
- `chapters/`：已接受正文。
- `drafts/`：Agent 候选。接受后原子写入对应 `chapters/ch_NN.md`。
- `tasks/`：一次配方运行的步骤与状态。

`services/api` 继续做薄文件服务。新增：读写上述文件、从 `characters.json` 生成 `relations.md`、创建/更新任务、接受/丢弃草稿。

### 4.1 `relations.md` 投影格式

```text
# Characters
- id: liora
  name: 莉奥拉
  role: 档案员
  goal: …
  knows: …

# Relations
- from: liora
  to: kael
  kind: ally
  label: 同盟
  tension: 潮图秘密
```

图谱保存时重写该文件。前端渲染只用 `characters.json`。

## 5. Agent 与 GUI 工作流

内核：本机 hermes-agent（`AIAgent` 循环）。API：`127.0.0.1:8642`。不自研 Orchestrator。

### 5.1 角色

| 角色 | 对应 | 职责 |
|---|---|---|
| 主笔 Echo | hermes 默认会话 | 对话、解释、触发配方 |
| 情节顾问 | `@plot-architect` | 结构、转折、一幕是否站得住 |
| 人物声音 | `@character-voice` | 对白是否 OOC |
| 世界观考据 | `@worldbuilding-check` | 只对照 `world.md` 指出冲突，不改文件 |
| 结构 | `@story-architect` | 现有 mock 子代理，用于幕/卷拆章 |

`/` Skill 至少：`/scene-drafting` 单章、`/draft-act` 一幕、`/draft-volume` 一卷、扩写、润色、续写。

### 5.2 三种配方（本小说工作流）

范围写在 `project.json` 的树里：卷包含幕，幕包含章。

| 配方 | 范围 | 产出 |
|---|---|---|
| 单章 | 一个 `ch_NN` | `drafts/<task>/ch_NN.md` |
| 一幕 | 该幕全部章，按序 | 每章一份候选 |
| 一卷（副本） | 该卷全部幕与章，按序 | 每章一份候选；大范围默认暂停在每幕结束等作者点继续 |

「副本」= 一卷。不是全书，不是文件复制。

每步对作者可见（任务卡）：

1. 读上下文：`outline.md` 相关段、`relations.md`、`world.md`、`canon.md`、邻章摘录
2. 起草：写入 `drafts/`
3. 自检：对照关系与世界，把问题写进任务日志（不自动改设定）
4. 落候选：状态 `awaiting_accept`
5. 作者接受或丢弃；接受才进 `chapters/`

工具权限：hermes 工具只能读写当前 `<book-id>/`。禁止改 `world.md` 与 `characters.json`，除非任务类型是「建议补设定」且作者在 GUI 点接受。

### 5.3 任务看板 GUI

任务页参考 Mirroric 看板，不参考其节点画布：

- 列：排队 / 进行中 / 待接受 / 完成
- 卡片：配方名、范围（卷/幕/章）、当前步骤、模型
- 点开：步骤时间线、日志、候选 diff、接受/丢弃/继续下一章
- 写作页右侧 Echo 可「委派」当前章到单章配方，与任务页是同一 `tasks/` 记录

运行中可停止。停止不删除已落盘候选。

## 6. 各页行为

### 6.1 写作

三栏：章树（卷/幕/章）、正文编辑器（现有自动保存）、Echo（Composer：附件、模型、`/`、`@`）。无语音。

章树数据来自 `project.json` + 各章字数。空章可新建，只加文件与树节点，不跑 Agent。

### 6.2 大纲 / 世界观

单栏 Markdown。保存走 api 原子写。世界观页文案标明：这是设定编辑，不是聊天。

### 6.3 人物 / 关系

人物：列表 + 详情表单，写 `characters.json`，保存后投影 `relations.md`。

关系：现有图谱交互。改边改点即写 json 并投影。Agent 上下文组装禁止把 json 原样塞进提示。

### 6.4 首页

保持笔心视觉。卡片与侧栏应对到真实文件计数（章数、字数），不再用假进度也可以先接 `project.json`。

## 7. 进程与桌面

本地三进程：

1. Vite / Electron 渲染笔心 UI
2. `services/api` `127.0.0.1:8787`
3. hermes API `127.0.0.1:8642`

MVP 桌面：启动时拉起 api；hermes 若未监听则 Echo 离线提示（已有）。下一小步再把 hermes 收进 Electron 子进程。

Dev 代理保持 `/api` → 8787、`/hermes` → 8642。

## 8. 错误与降级

- api 不可达：编辑器只读，任务页提示
- hermes 不可达：Echo 离线，已排队任务不开始
- 配方中途失败：任务 `blocked`，已完成章的候选保留
- 投影失败：保存人物/关系时提示，不写一半 `relations.md`

## 9. 测试

- api：章 CRUD、投影 `relations.md`、接受草稿的原子写
- 图谱保存后 `relations.md` 不含坐标字段
- 任务状态机：单章跑完为 `awaiting_accept`；接受后 `chapters/` 有正文、`drafts/` 可删
- Echo：`/` 插入 Skill、`@` 插入专家、发送带所选模型（已有 Composer 测试须保持）
- 世界观保存不触发 Agent

## 10. YAGNI

不做：通用工作流画布、伏笔模块、灵感库后端、线索系统、RAG、模型路由服务、发布审查、多书云同步、圆桌、拆书。

15 篇编号规格仍是远期地图，本 MVP 不按其数据模型建库。

## 11. 落地顺序

1. 文件契约 + 投影 `relations.md`
2. 大纲页、世界观页接到真实 md
3. 人物/关系接到 `characters.json` 并投影
4. hermes 工具锁定当前书目录
5. 三个 Skill 配方 + 任务卡
6. 写作页委派与接受候选
7. 桌面启动 api（hermes 仍可外部）

你自己验收：改一处关系 → 跑单章 → 候选里能看出用了新关系；改 `world.md` 一条规则 → 世界观考据能指出正文冲突；跑一幕会按章暂停等你接受。

## 12. 文案与视觉

UI 中文（笔心）。可见文案不用 em-dash。写作台继续白绿液态玻璃；任务卡时间线参考 Mirroric 的条目 + 状态，配色仍用现有 mint 令牌，不搬镜界水墨主题。
