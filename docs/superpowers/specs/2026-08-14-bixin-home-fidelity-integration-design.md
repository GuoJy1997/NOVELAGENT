# 笔心首页高保真整合设计

**日期：** 2026-08-14  
**状态：** 已由用户逐节确认  
**范围：** 将已确认的“笔心”首页视觉整合进当前 `novel-agent` 仓库  
**首要目标：** 在 1672 × 941 下严格还原确认参考图，同时保留当前项目的数据、交互和可访问性语义

## 1. 决策摘要

本次采用“结构级重构、业务逻辑复用”方案，不继续在旧 Echo 首页骨架上叠加 CSS。

首页将拥有独立的 `BixinHomePage` 组合层。旧实现中可复用的本地 fixture、状态回调、写作入口和 Testing Library 语义继续保留；固定画布缩放、旧 Echo 顶栏、旧侧栏、旧玻璃令牌和压缩到 300px 的 Dashboard 布局全部退出首页。

参考图是实现结果的视觉上限和唯一构图基线。实现过程不得自由改造为“更现代”“更酷”或其他风格，也不得把参考图或卡片截图直接作为页面 UI。

3. `2026-08-14-bixin-desktop-home-visual-design-system.md` 中的品牌与首页视觉宪章。

## 3. 范围

### 3.1 本轮包含

- 笔心首页外框、导航轨、品牌区、Topbar、Hero、三层场景和 Dashboard。
- 六个 Dashboard 模块及其本地 Mock Data。
- 首页主要 CTA、导航选中态、搜索框聚焦和 Demo 状态反馈。

- 首页组件测试、CSS 契约测试、资产注册测试和浏览器视觉 QA。

### 3.2 本轮不包含

- 写作工作区的视觉重构。
- 项目、大纲、人物、统计、世界观等完整业务页面。
- 后端、数据库、持久化、真实搜索、真实 Agent、RAG、云同步或多窗口业务。
- Tailwind 迁移或仓库级内部类型重命名。
- 为未实现导航项伪造完整页面。

## 4. 方案选择

评估过三种方案：

1. **结构级重构，复用业务逻辑（采用）。** 高保真、边界清晰，能移除造成当前错位的根因。
2. **在旧结构上继续覆盖 CSS（拒绝）。** 改动表面较小，但绝对顶栏、固定画布和 300px Dashboard 会持续相互制约。
3. **大量绝对坐标复刻（拒绝）。** 单一尺寸接近参考图，但窗口变化后脆弱，也不利于组件测试和后续演进。

## 5. 页面骨架

### 5.1 视口模型

- 1672 × 941 是直接视觉对照视口。
- 1728 × 972 是产品设计与 Electron 默认窗口基准。
- 1440 × 810 是最小支持窗口。
- 删除整页 `transform: scale()`、`--echo-scale` 和居中 letterbox 偏移。
- 1920px 及更宽窗口保持主体比例并居中，不横向拉伸卡片。
- 1440 × 810 通过收紧间距、字体和卡片内部尺寸适配，不缩放整个 DOM。
- 低于最小支持窗口时允许滚动，不压扁文字、按钮和图像。

### 5.2 1672 × 941 构图锚点

下列数值用于首轮几何校准，最终以参考图叠加结果为准：

- 外层应用容器：距视口约 16px，约 28px 圆角，轻中性阴影。
- 左侧导航轨：约 x=16–128，宽约 112px。
- 主场景区：从约 x=128 延伸到应用容器右缘。
- 品牌文字：约 x=151，y=47。
- Hero 文案：约 x=197，y=143；主标题约 72px。
- Dashboard 顶边：约 y=473。
- 第一列：约 x=157–653，项目卡跨两行。
- 第二列：约 x=666–1163，上方章节进度、下方写作目标。
- 第三列：约 x=1177–1624，上方人物关系、下方日程与日历。
- 列间距和行间距以 14–16px 为主。
- 书本主体约位于 x=916–1328、y=285–464；书签允许继续向下进入人物关系卡的非功能留白。

在 1728 × 972 下通过容器和网格规则自然扩展这些关系，不对整个页面进行 transform 缩放。

### 5.3 信息架构

- 左侧导航只包含应用图标、首页/项目/大纲/人物/统计/世界观、设置和用户信息。
- “笔心 / AI写作工作室”位于场景左上方，不挤在导航轨内部。
- Topbar 只保留搜索、通知和帮助。
- 项目名称、状态和数据回到“我的项目”卡片。
- “继续写作”和“新建项目”位于 Hero。
- Dashboard 卡片数量严格保持参考图，不添加新模块。

## 6. 三层空间架构

```text
Canvas / outer desktop frame
├── SceneLayer                 背景、云层、浮空岛、机器人
├── InterfaceLayer             品牌、导航、Hero、卡片、文字与交互
└── BookForeground             书本、立体地图、书签
```

### SceneLayer

- 使用 handoff 中的原始 `scene_robot_background.png`，尺寸 1672 × 941。
- 实施时复制并注册到 `apps/web/src/assets/bixin/`，运行时代码不得直接引用 `assets/extracted-handoff/`。
- 场景覆盖完整应用容器并延伸到 Dashboard 后方，不裁成 700px Hero Banner。
- 不重新生成、调色、锐化或把书本合并进该图。
- `pointer-events: none`。

### InterfaceLayer

- 全部文字、卡片、导航、按钮、图表和关系线由 React 与 CSS 实现。
- 不使用参考截图切块，不把卡片渲染成图片。
- 交互内容必须保持真实 DOM 和可访问语义。

### BookForeground

- 使用 handoff 中独立的书本前景资产；实施时复制并注册到 `apps/web/src/assets/bixin/`。
- `pointer-events: none`。
- 书角只可压住人物关系卡上缘约 8–18px 的非功能区域。
- 书签只可进入约 16–30px 的非功能留白。
- 不得遮挡卡片标题、人物头像、名称、关系线交汇区、按钮和状态数据。
- 必要时将卡片表面、书本和卡片内容拆成局部层级，避免单一全局 z-index 压住所有功能内容。

## 7. 组件架构

首页与写作工作区隔离：

```text
App
├── BixinHomePage
│   ├── SceneLayer
│   ├── NavigationRail
│   ├── BrandHeader
│   ├── HomeTopbar
│   ├── HeroSection
│   ├── HomeDashboard
│   │   ├── ProjectOverviewCard
│   │   ├── ChapterProgressCard
│   │   ├── CharacterNetworkCard
│   │   ├── WritingGoalsCard
│   │   ├── SceneScheduleCard
│   │   └── CalendarCard
│   └── BookForeground
└── WritingView
```

### 7.1 组件责任

- `BixinHomePage` 只负责页面组合和层级。
- `NavigationRail` 只负责导航显示和选中回调。
- `HomeTopbar` 只负责搜索、通知和帮助控件。
- `HeroSection` 只负责品牌叙事文案和两个 CTA。
- 每张 Dashboard 卡片只接收数据和回调，不读取全局状态。
- 场景和书本组件不依赖 Dashboard DOM。

### 7.2 样式边界

- 新增 `bixin-home.css`，不继续扩展已超过 3000 行的 `echo.css`。
- 共用语义颜色、字体、圆角、阴影和动效令牌放入 `tokens.css`。
- 新首页组件使用 `bixin-*` 类名，不依赖 `echo-*` 选择器。
- 旧 `echo.css` 继续服务未迁移界面。
- 新首页不使用 `--echo-glass-*`、旧渐变按钮或全局缩放变量。

## 8. 品牌与视觉系统

### 8.1 品牌

- 对外品牌固定为“笔心”。
- 副标题为“AI写作工作室”。
- 首页不出现 Echo、Novelora 或英文产品标题。
- 使用 handoff 中已存在的 `bixin_app_icon.png` 原始资产，尺寸 1254 × 1254；不重新生成、不用 CSS 或临时 SVG 仿制。

### 8.2 字体

- 品牌和 Hero：`Noto Serif SC`, `Songti SC`, `Source Han Serif SC`, serif。
- UI 和正文：`PingFang SC`, `Microsoft YaHei`, `Noto Sans SC`, sans-serif。
- Hero 主标题约 68–76px、600 字重、紧凑行高；“故事”使用品牌绿。
- 卡片标题约 17–19px，正文约 13–15px。
- 不依赖联网字体。

### 8.3 材质

- 主卡片约 `rgba(255,255,255,.88)`，局部 `blur(8px)`。
- 边框约 `1px solid rgba(255,255,255,.70)`。
- 圆角约 24px。
- 阴影轻且中性，不使用薄荷发光。
- 主按钮使用 Green 600 实色，Hover 使用 Green 700。
- 禁止渐变按钮、蓝色 SaaS 主色和遍地胶囊控件。
- 卡片间距约 16px，卡片内边距约 20–24px。

### 8.4 图标与内容资产

- 图标使用同一套线性图标库，约 1.75px 描边；优先 Lucide React。
- 不混用旧 Novelora 图标、Emoji、文本符号和临时手绘图形。
- “我的项目”使用 handoff 中的项目封面，显示尺寸约 160px。
- 人物关系使用已有真实人物肖像，不使用首字母圆圈。
- 视觉顺序必须是：Hero 标题 → 机器人观察书中世界 → 书本 → 项目与进度 → 辅助卡片。

## 9. 数据与交互

顶层 `App` 继续管理：

- 首页/写作视图状态。
- 当前导航项。
- 当前写作章节。
- Demo 操作反馈。

首页数据继续来自本地 fixture，但显示内容调整为参考图对应的中文项目、章节、人物、目标、日程和日历。组件不得在 JSX 中硬编码大块业务数据。

交互合同：

- “继续写作”和“打开项目”进入当前章节的 `WritingView`。
- “新建项目”显示明确的 Demo 状态反馈，不创建真实项目。
- 导航更新 `aria-pressed`；未实现页面不伪造业务结果。
- 搜索框支持输入和快捷键聚焦，本轮不制造虚假搜索结果。
- 次要操作通过现有 `role="status"` 反馈说明 Demo 边界。
- 搜索、通知和帮助以可操作控件呈现；超出本轮功能范围的结果可以是解释性反馈。

## 10. 异常、适配与可访问性

- 核心品牌、场景、书本、封面或人物资产缺失时，由 asset registry 测试失败暴露问题，不静默显示临时占位图。
- 装饰图使用空 `alt`；有信息意义的人物头像使用人物名称。
- 所有主要点击目标至少约 44 × 44px。
- 键盘焦点必须可见，DOM 阅读顺序与视觉顺序一致。
- 书本不能拦截鼠标或键盘事件。
- `prefers-reduced-motion` 下停止云层、机器人和卡片悬浮动画。
- 首屏不得存在非预期滚动条、内容裁切或焦点陷阱。

## 11. 测试与视觉 QA

### 11.1 交互测试

- 中文品牌和导航文案正确。
- 六张首页卡片全部存在。
- CTA 回调和写作入口正常。
- 导航 `aria-pressed` 状态正确。
- 搜索、按钮和信息图像拥有正确可访问名称。
- 操作反馈继续使用 `role="status"`。

### 11.2 CSS 契约测试

- 首页不存在全局 `transform: scale()`。
- SceneLayer 覆盖完整应用容器。
- BookForeground 为 `pointer-events: none`。
- 首页不依赖旧 `--echo-glass-*` 和渐变令牌。
- 存在 1440 × 810 适配和 reduced-motion 规则。
- 首页关键几何、图层和令牌保持可审计。

### 11.3 资产测试

- 注册并锁定笔心图标、场景、书本、项目封面和人物肖像。
- 资产路径由 `assetRegistry.ts` 管理。
- 核心图片可读取，书本 SVG（若使用）可解析。

### 11.4 视觉 QA

每次使用相同视口和相同页面状态，将参考图与实现截图放在同一对比输入中检查。

1. 宏观构图：外框、导航、Hero、机器人、书本、Dashboard 起始线和卡片边界。
2. 组件比例：字体、封面、头像、进度环、按钮、图标和内边距。
3. 精细抛光：阴影、边框、透明度、行高、关系线、Hover 和轻动效。

第一轮未对齐时，不进入阴影和动画微调。截图本身不能替代并排比较。
