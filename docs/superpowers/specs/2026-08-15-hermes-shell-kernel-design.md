# 笔心：Hermes 小说壳内核设计规格

日期：2026-08-15
状态：已评审

笔心是套了小说主题的 hermes-agent 壳，不是另做一套编排内核。权威视觉仍是 Codex 笔心（`http://127.0.0.1:4173/` 与 `2026-08-14-bixin-desktop-home-visual-design-system.md`）。本规格定双通道内核与对话框 MVP；不引入第二套 UI。

相关文档：

- 工作台页面与文件：`2026-08-15-local-mvp-workbench-design.md`（文件布局仍用；`/` `@` 写死小说目录、Agent 禁止写设定，以本文为准）
- 笔心壳：`2026-08-15-bixin-shell-workbench-design.md`
- 远期地图：编号规格 08 / 09 / 10 / 14（本规格不按其全量实现）

## 1. 精髓

作者面对的是小说页（人物卡、大纲、章节、工作流画布、对话框）。底下是一本小说目录和一台本机 Hermes。

- 页面是皮，文档是骨。人物、关系、大纲、世界观由文件渲染。
- Agent 和 coding agent 一样可以改文件；安全阀是候选、审核、接受、丢弃，不是禁止写 `world.md`。
- `/` 和 `@` 弹出的是 Hermes 自己有的技能、命令、内置专家，不是前端写死的小说菜单。以后在 Hermes 侧把清单换成小说写作相关，壳不换。
- 不自研 Orchestrator。对话框怎么规划，跟 Hermes 怎么规划，一回事。

## 2. 三层

1. **笔心**：把文件画成小说页；把候选画成可审、可收、可弃；对话框把话、`/`、`@` 交给 Hermes，并把 Hermes 的 todo / 工具过程原样亮出；工作流画布只负责让作者摆节点和线。笔心不规划步骤，不跑模型。
2. **文件核（`services/api`）**：一本小说一个目录。真文件与候选区分开。工作流的图也存在这本书目录里。不决定下一步该干什么。
3. **Hermes**：唯一会思考的东西。对话框是 Hermes 原生循环。工作流是按作者预制的图，一节点一轮。

直播 UI 只有笔心。不准再做 Echo 白壳、mint 驾驶舱或并行首页。

## 3. 两条通道

| | 工作流 | 对话框 |
|---|---|---|
| 谁排步骤 | 作者预制，精打细算 | Hermes 自主（ReAct、plan-and-execute、todoList 等，跟 Hermes 本身走） |
| 入口 | 没有对话入口 | 作者用语言描述目标 |
| 一轮是什么 | 节点目标 + skill 提示词 + 专家提示词 + 上游附件 | 作者的话 + 插入的 Hermes `/` 与 `@` |
| 规划可见性 | 节点和线 | Hermes 的 todo，不画成节点图 |
| 改文件 | 先落候选 | 先落候选 |

两条通道进同一个核：都读真文件，都只写候选，都经作者接受才覆盖真文件。

## 4. 文件与候选

真文件（沿用工作台目录）：

- `project.json`
- `outline.md`、`world.md`、`canon.md`
- `characters.json`（图谱源）与投影 `relations.md`（给 Agent 读关系只读这一份）
- `chapters/ch_NN.md`
- 工作流图（本书目录内，格式在实现计划里定，须可版本化）

候选：

- 一条候选对着一个真文件路径。
- 落在 `drafts/<run-id>/`，按真文件相对路径存放，并记录来源（对话 / 某工作流节点）与待审状态。
- 接受：原子写入真文件，再清这条候选。
- 丢弃：只删候选，真文件不动。
- MVP 不做接受之后的历史回滚。
- 探索结果、审查意见、todo 过程不是候选。只有「打算改某个真文件」才是候选。

对话框 MVP 先打通章节正文候选。大纲 / 世界观候选走同一套核，不要求这一刀做完。

Agent 上下文组装禁止把 `characters.json` 原样塞进提示，只给 `relations.md` 与其它 markdown。

## 5. 对话框 MVP（最小清单）

打通即可，不先换小说技能包。

1. 在笔心里说话，打到本机 Hermes。todo / 工具过程按 Hermes 原生展示。
2. Hermes 能读当前书目录真文件（大纲、世界观、关系、已有章）。工具范围锁在当前书。写操作只许进候选区。
3. 章节候选可审、可接受进 `chapters/`、可丢弃。
4. `/` 弹出 Hermes 当前技能与命令清单；`@` 弹出 Hermes 当前内置专家清单。列表必须从 Hermes 读取（实现计划须对准 Hermes 真实清单接口或等价发现方式）。没有清单就显示空，禁止回退到前端写死的 `ECHO_SKILLS` / `ECHO_EXPERTS`。插入的是 Hermes 会吃的原 token，随消息发送。
5. 人手保存世界观 / 大纲 / 人物不召唤 Agent。

明确不做（本 MVP）：

- 前端写死的小说 `/` `@` 目录（现有 `EchoComposer` 里的单章起草、情节顾问等须换成 Hermes 清单）
- `@` 启动 Multi-Subagents 或「规划全局」专家（等 Hermes 侧以后出现再接）
- 把对话 todo 画成工作流节点图
- 工作流画布当对话产物
- 圆桌、RAG、第二套编排器、5173 另一套皮

以后换血：在 Hermes 里替换技能、命令、专家为小说写作相关。笔心仍读同一套清单接口。

## 6. 工作流通道（内核先定，画布后做）

一个节点是一轮冻住的 Hermes：节点目标 + 选中的 skill + 选中的专家 + 上游附件。没有对话入口。模型不能改路线、不能自己加节点。

- **探索节点**：读世界观 / 人物关系 / 状态 / 大纲。只读真文件，产出附件，不写候选。
- **动手节点**：写大纲、写某一章或某个子故事正文、去 AI 味、审查、最终产出。改文件只写候选。审查意见是附件；最终产出指向的文件在作者接受后才进真文件。

线只传附件，不传聊天。粒度写在节点目标里（第 15 章，或全书里某一个子故事）。

图存在这本书目录。文件核按拓扑跑；Hermes 只跑每一轮。笔心以后只负责摆节点和看状态。

对话框 MVP 不跑这张图。现有「单章 / 一幕 / 一卷」配方暂时继续当预制工作流的替身，画布落地后再换成作者自编图。

## 7. 出错

- Hermes 不在：对话框离线，不写新候选，已有候选保留。
- 某一轮失败（对话一步或工作流一节点）：停在失败处，已落候选不删，真文件不动。
- 接受失败：真文件保持接受前状态，候选仍在，可重试。
- 工作流缺上游附件：该节点不跑，标受阻，不让 Hermes 编造上下文。

## 8. 测试与验收

文件核：候选写入、接受原子落盘、丢弃、失败不碰真文件。

前端：

- `/` `@` 弹出的条目来自 Hermes 清单，而不是 `ECHO_SKILLS` / `ECHO_EXPERTS` 常量
- 离线提示
- 章节候选审 / 收 / 弃
- 可见中文，无 `—` / `–`
- 人手保存世界观不打 Hermes

验收：在笔心里说话，能看见 Hermes 的 todo / 工具过程；能读到当前书文件；写出的章只在候选里；接受后才进 `chapters/`；`/` `@` 能插入 Hermes 现有项。

## 9. 落地顺序

1. 候选核（章节先，路径可指向任意真文件）
2. 对话框接到 Hermes 原生循环，工具锁书目录、只写候选
3. `/` `@` 改为读 Hermes 清单
4. 笔心写作页只留这一套助手，去掉假技能表
5. 工作流图存储与按节点跑（无画布也可先用文件/测试夹具）
6. 笔心工作流画布（另开计划）
7. Hermes 侧替换小说技能 / 命令 / 专家（另开计划）

## 10. 与旧规格冲突时

以本文为准的：`/` `@` 数据源、Agent 可对设定写候选、工作流是作者预制图而不是写死五步（五步配方仅过渡）、不自研规划器。

仍有效的：笔心唯一直播 UI、`relations.md` 投影、api `8787`、hermes `8642`、不引入 Tailwind。
